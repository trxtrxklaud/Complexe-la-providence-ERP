**طبيعة الوثيقة:** Mandatory Pre-Deployment Gate Checklist

## 1. شروط الأمان المعمارية الإلزامية (Architectural Hard Gates)

- [ ] **1.1 اكتمال تعريف نوع رسم الحضانة:**  
  إنشاء هجرة رسمية لقاعدة البيانات تضيف الفهرس الفريد والرمز البرمجي الثابت `code = 'CHILDCARE'` لجدول `fee_types`، والتأكد التام من عدم وجود أي استدعاء صلب للمعرف `5` في الكود البرمجي.
- [ ] **1.2 حسم نموذج الحضانة رسمياً:**  
  استلام اعتماد خطي من مالك النظام يحدد هل الحضانة اشتراك شهري فريد (نموذج A) أم خدمة متكررة عند الطلب (نموذج B).
- [ ] **1.3 سلامة بيئة الاختبار:**  
  تشغيل كامل حزمة الاختبارات الآلية (`php artisan test`) والتأكد من نجاح 100% من الاختبارات دون أي فشل أو تحذيرات نقدية.
- [ ] **1.4 التحقق من سلامة النسخة الاحتياطية:**  
  إجراء اختبار استعادة تجريبي للنسخة الاحتياطية في خادم Staging معزول للتأكد من قابلية استرجاع البيانات بالكامل.

## 2. مصفوفة خطوات النشر الميداني (Deployment Runbook)

### المرحلة الأولى: ما قبل النشر (Pre-Deploy)
1. أخذ نسخة احتياطية جديدة كاملة (`mysqldump`) من قاعدة الإنتاج والتحقق منها بـ `gzip -t`.
2. تفعيل وضع الصيانة (`php artisan down --secret=...`) إذا تطلب الأمر تشغيل هجرات للجداول الحساسة.

### المرحلة الثانية: النشر التدريجي (Feature Flag & Phased Rollout)
1. دمج فرع الكود المعتمد (`git pull origin main`).
2. تنفيذ هجرة ضبط الرمز البرمجي `php artisan migrate --force`.
3. التحقق من كاش الإعدادات والتوجيه:
   ```bash
   php artisan config:cache
   php artisan route:cache
   ```
4. إطلاق الميزة تدريجياً:
   - **اليوم 1:** تفعيل نصف الشهر لمستوى الروضة (`PRE1`) لشهر سبتمبر فقط ومراقبة القيود المسجلة في `cash_transactions`.
   - **اليوم 2:** تفعيل التمهيدي (`PRE2`) والتحضيري (`PRE3`).
   - **اليوم 3:** تفعيل معلوم الحضانة ومراقبة تقارير الصندوق اليومية.

## 3. خطة الطوارئ والتراجع العكسي (Rollback Strategy)

في حال حدوث أي خلل مالي أو عدم تطابق في رصيد الخزينة:
1. **التعطيل الفوري عبر Feature Flag:**  
   تعطيل خيار نصف الشهر والحضانة في واجهة الاستخلاص فوراً دون الحاجة لإعادة نشر الكود.
2. **عزل المعاملات المشبوهة:**  
   مراجعة القيود المنشأة عبر استعلام المطابقة اليومي:
   ```sql
   SELECT p.id, p.amount, ct.amount, ct.category
   FROM payments p
   JOIN cash_transactions ct ON ct.source_id = p.id AND ct.source_type = 'App\\Models\\Payment'
   WHERE p.payment_date = CURRENT_DATE;
   ```
3. **التراجع البرمجي:**  
   الرجوع إلى آخر Commit مستقر عبر Git، وإعادة بناء الفرونت إند (`npm run build`).
